# 책에서 그림과 텍스트를 어떻게 처리하나

> **텍스트와 그림은 처리가 다르다.** 텍스트는 전사해서 갖고, **그림은 안 갖는다.**
> 왜 안 갖는지가 이 문서의 절반이고, 그게 [02-화면-자동-갱신](02-화면-자동-갱신.md)으로 이어진다.

## 먼저 — 지켜야 할 선

- 출판물은 **문장을 옮기지 않는다.** *무엇이 문제이고 어떻게 푸는지*를 **내 문장으로 다시 쓴다.**
- 인용은 **짧게 · 따옴표 · 출처.**
- 지면 이미지를 교안에 그대로 싣지 않는다. **다시 찍거나 그린다.**
- 용도는 **개인 학습·강의 재료 준비.** 원문 지면의 재배포는 별개 문제다.

# 1부 · 텍스트

## 3단계

| | 무엇 | 실측 교훈 |
|:--:|---|---|
| 1 | **캡처** — 화면을 PNG로 | **영상 녹화 후 프레임 추출 ✗** — 같은 쪽 실측에서 OCR 일치율이 **88~92%로 떨어졌다.** PNG는 무손실인데 **용량도 더 작다** |
| 2 | **전사** — OCR로 텍스트 원고 하나 | 원고에 **쪽 표시**(`<!-- page 58 -->`)를 심는다 → 나중에 **구간만 다시** 뽑을 수 있다 |
| 3 | **위임** — 원고를 절 단위로 AI에게 | **한 번에 한 절.** 여러 절을 한꺼번에 시키면 **파일 번호가 충돌한다** |

### 캡처할 때

- **한 번에 한 쪽씩, 화면을 세로로 회전해서** 찍는다.
  촬영 횟수가 2배가 되지만, 해상도를 정하는 기준은 **글자가 아니라 그림 품질**이다.
  글자만 보면 작아도 OCR이 읽지만, 나중에 그림을 잘라 쓸 때 원본이 작으면 못 쓴다.
- 가로 화면에서 세로 1쪽을 찍으면 좌우가 여백이 되어 이득이 없다 — **회전이 조건.**

### 전사할 때

- **PDF면 먼저 텍스트층이 있는지 본다.** 한글·PPT·워드에서 내보낸 PDF는 글자가 이미 파일 안에 있다.
  그런데도 지면을 렌더해 다시 OCR하면 **GPU 시간을 쓰고 원문을 정확도만큼 깎는다 — 두 번 손해다.**
- **PPT에서 나온 PDF는 텍스트가 조각나 있다.** 실측 블록 중앙값 **3자**, 97%가 10자 이하였다.
  같은 줄·같은 크기·바로 옆인 것만 **좁게** 붙인다. 넓게 붙이면 도표 안 라벨까지 이어져 틀린다.

## 전사본 → 시드 프롬프트

```
아래 전사본에서 지정한 구간만 읽고 재사용 가능한 시드로 분해해줘.

- 문장을 그대로 옮기지 마라. 무엇이 문제이고 어떻게 푸는지를 네 문장으로 다시 써라
- 목차 단위로 자르지 마라. 따로 꺼내 쓸 수 있는 단위로 잘라라 (한 꼭지가 보통 2~4개)
- 조작법(메뉴 이름·클릭 경로·버튼 위치)은 버려라. 도구가 바뀌면 죽는다
  단 도구와 무관하게 유효한 성질은 남겨라
  (예: "불투명도와 투명도는 수치 방향이 반대라 값을 그대로 옮기면 반대가 된다")
- 그림이 필요하면 경로를 지어내지 말고, 원고에 있는 파일명을 그대로 figures_todo 에 적어라
- 뜻이 통하지 않는 인식 오류 조각은 버려라. 애매하면 버려라
- 한 번에 한 절만. 여러 절을 한꺼번에 시키지 마라
```

**왜 "한 번에 한 절"인가** — 구간을 나눠 독립 실행하면 **파일 번호가 반드시 어긋난다.**
방식의 문제가 아니라 분할의 성질이다. 나중에 한 번에 재번호를 매기는 편이 낫다.

> ⚠️ **누락은 조용하다.** 전권을 훑었다고 믿었는데 한 장(12시드)이 통째로 빠진 채
> "완료"로 기록된 적이 있다. **AI에게 맡긴 작업은 "했다"는 말이 아니라 "안 한 자리"로 확인한다.**
> 전사 원고가 남아 있으면 **어느 구간을 안 훑었는지** 기계적으로 셀 수 있다.

# 2부 · 그림 ← 여기가 자동 갱신으로 이어진다

## 갖지 않는다. 찍을 목록만 남긴다

```yaml
figures_todo:
  - source: 049_04_Table.png   # 쪽·블록 식별자 — 필요할 때 원본에서 뽑는다
    want: 매장 정보 표            # 무엇이 보여야 하는가 = 교안에 찍거나 그릴 것
```

## 왜 안 갖나 — 실측 셋

| 근거 | 수치 |
|---|---|
| **대부분이 UI 스크린샷이다** | 시드가 참조한 그림 **147개** 중 `want`가 거의 다 "…화면"(가입 화면·설정 화면·클릭하는 화면) |
| **어차피 낡는다** | 2026년 3월에 나온 책의 화면은 **교안 만들 때 이미 낡았다** |
| **크롭이 용량의 98%였다** | 산출물 214MB 중 크롭이 **209MB.** 지우니 **5.0MB** |

**그리고 지워도 잃지 않는다** — 쪽 픽셀 크기·bbox·라벨·읽기순서가 JSON에 있어서
원본만 있으면 **픽셀 단위로 재현된다**(243개 전수 대조, 불일치 0).

- **저작권상도 재촬영이 안전하다.** 지면을 그대로 싣는 것보다.
- **품질도 낫다.** 재촬영하면 최신 화면이 들어간다.

> ⚠️ **`figures_todo` 는 미완성 표시가 아니라 작업지시서다.** 남아 있는 게 정상이다.

## 필요할 때 뽑는 법

- **그림 하나**가 아니라 **쪽 통째로** 뽑는 게 대개 낫다 — 재촬영·작도할 땐 앞뒤 지시문이 같이 보여야
  뭘 찍을지 안다.
- ⚠️ **배율을 픽셀에서 되계산하지 마라.** 원본은 정수 dpi로 렌더하고 `px = int(w_pt/72*dpi)` 로
  **절삭**하므로, px에서 얻은 배율은 아주 조금 작다. **크기는 같은데 픽셀이 어긋난다**(실측 243개 중 173개).
  `dpi = round(w_px*72/w_pt)` 로 **정수 dpi를 복원**해야 한다.
  ⇒ **"크기가 같다"를 "같은 그림이다"로 읽지 마라.**

## 그다음 — 자동 갱신으로 넘긴다

`figures_todo` 의 `want` 가 대부분 **서비스 화면**이다. 그러니까 **낡을 운명**이다.

1. 교안을 만들 때 그 목록을 `tools/shots.txt` 로 옮긴다.
2. `python capture_pages.py` 로 한 번에 찍는다.
3. 반년 뒤 `--stale 180` 이 낡은 것을 지목한다.

→ [02-화면-자동-갱신](02-화면-자동-갱신.md)

---

## ⚠️ 이 방식이 못 건지는 것

전사는 **텍스트만** 넘긴다. 그래서 저자가 프롬프트를 본문 활자가 아니라 **화면 스크린샷으로 실은 곳**은
시드에 원문이 안 들어온다. 실측: 전사된 프롬프트 블록 9개 · 그림으로만 실린 것 **5곳**.

**치명적이지 않다** — 시드가 `figures_todo` 로 그 그림을 지목하므로 **누락이 아니라 포인터**로 남는다.
그림째 읽어야 하면 그 쪽만 멀티모달 모델에 따로 넘기면 된다.
